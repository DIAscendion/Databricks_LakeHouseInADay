# Databricks Bronze Model Physical: TMS Shipment Application

This document defines the physical data model for the Bronze layer of the Databricks Lakehouse, focusing on the SHIPMENT entity and its related audit structure. The model is designed for raw data ingestion, governance, and lineage tracking, using Delta Lake tables compatible with Databricks SQL and PySpark.

## Assumptions and Design Decisions

- All columns from the SHIPMENT logical model are included as-is, with data types mapped to Databricks SQL (STRING for VARCHAR, TIMESTAMP for DATETIME, DECIMAL as specified, INT as integer).
- No primary keys, foreign keys, or constraints are enforced at the Bronze layer (Delta tables do not enforce them).
- Metadata columns (load_timestamp, update_timestamp, source_system) are added for governance and lineage.
- Audit table is provided for tracking ingestion and processing events.
- Table names follow the convention: bronze.bz_<tablename>.
- Only the SHIPMENT table is physically modeled here, as it is the main entity in the provided input. Other entities (CARRIER, FACILITY, etc.) can be modeled similarly if required.
- All fields are nullable unless otherwise specified in the source.
